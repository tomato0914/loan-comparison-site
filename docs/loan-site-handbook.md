## 2. 集めるデータ項目（1商品ごと）※作業中に追加した項目あり

各商品について、次をそろえる。これが比較表の材料になる。

- 銀行名 / 商品名
- **金利（実質年率）**：下限〜上限（固定か変動かも記録）

- **申込可能エリア**：地域しばりの有無　←追加
- 銀行口座：必要か不要か
- 保証会社
- Web完結できるか（来店不要か）
- 融資スピード（即日可か／数営業日か）　←追加
- **公式ページのURL**
- **◯年◯月時点**（確認した日）

## 3. ★作業で分かった「正確さのルール」（今回の重要ポイント）

1. **金利は「商品ページ」でなく「金利専用ページ／商品説明書PDF」で最終確認する。**
   商品ページは日付スタンプが古いままのことがある（例：京都銀行は商品ページが「2024年」表記でも、
   金利ページは新しく、数字は変わっていなかった）。

2. **他サイト（アフィリエイト比較サイト）の数字はうのみにしない。公式が唯一の正解。**
   実例：
   - 南都銀行 → 他サイトが金利をバラバラに掲載。実は商品が2種類あった（スマート/クイック）。
   - 紀陽銀行 → 他サイトは下限「4.45%」。公式は「4.7%」。
   → 公式の「商品説明書PDF」があれば、それがいちばん正確で日付も新しいことが多い。

3. **勤続年数・エリアは「公式が言っていないこと」を書かない。**
   多くの銀行は勤続年数の指定を公表していない（「安定継続収入」とだけ）。
   エリアも、公式条件に無ければ「記載なし」と正直に書く。推測で狭く書かない。

4. **変動金利の商品は、掲載値が動く前提。** 公開前に金利ページで最新値を再確認する。

5. **金利ページがJavaScriptで数字を後から表示する銀行がある（要注意）。**
   例：関西みらい銀行（りそなグループ）は、ページの見た目には「金利（新規） 年%〜%」のように
   記号だけが先に読み込まれ、実際の数字はあとからプログラムで書き換わる作りになっている。
   このため、自動でページを取得する方法では数字が空欄のまま拾えないことがある。
   → 対処法：とまとさんご自身がブラウザで実際にページを開き、**スクリーンショットを撮って共有**
   してもらうのが最も確実。りそなグループ系（りそな銀行・埼玉りそな銀行・関西みらい銀行・
   みなと銀行）は同じ作りの可能性があるため、同様の対応を想定しておく。
   （参考：この作りは、金利改定時に全ページを手作業で直さなくて済むよう、グループ共通のシステムから
   最新の数字を自動で呼び出して表示する仕組みと考えられる。古いキャッシュが残って誤った金利が
   表示される事故を防ぐ狙いもありそう。）

6. **銀行によっては「金利一覧」という専用ページ（例：/kinri.html）があり、そこがいちばん正確・最新。**
   商品ページや商品概要説明書PDFの日付が古くても（例：但馬銀行の商品LPは「平成30年」表記のまま
   だったが）、「金利一覧」ページは頻繁に更新されており、但馬銀行の例では「令和8年9月1日現在」＝
   ほぼ最新だった。数字も両ページで一致しており、内容自体は正確だった。
   → 銀行名＋「金利一覧」で検索し、専用ページがあればまずそこを確認する。

7. **「複数の古いページの数字が一致している」＝正しいとは限らない（重要な訂正）。**
   十六銀行Q-LOANでは、商品ページ（2018年表記）と複数のアフィリエイトサイト（2026年更新）が
   そろって「4.6%〜14.6%・限度額500万円」としていたため、いったん「一致している＝正しい」と
   判断した。しかし本人がスクショで確認した「金利一覧」ページ（2026年9月1日現在）では
   「2.0%〜14.95%・限度額800万円」に変わっており、限度額そのものが増額されていた。
   → 教訓：**古いページ同士の一致は「昔から変わっていない証拠」ではなく「同じ古い数字を
   参照し合っているだけ」の可能性がある。** 日付が古い場合は、一致していても鵜呑みにせず、
   「金利一覧」ページか本人によるスクショで最終確認するのが安全。限度額（上限）自体が
   増額されているケースもあるため、金利だけでなく限度額の数字も再確認する。

8. **「1行に複数のカードローンがあれば全部含める」方針（網羅性の方針）。**
   ただし住宅ローン利用者専用などの限定商品（十六=カードローンプラス、静岡=ネクストワン、
   但馬=STORK、あいち=NEO）は、一般向け比較表には載せず「注記のみ」にする。
   また、契約時の注意書きに出てくる旧商品名（例：みなと銀行の「Qポートネオ」「Qポート」
   「みなとアットローン」）は、**今も選べる別商品とは限らず、統合・廃止済みの旧名称のことがある**。
   実際にみなと銀行はQポートネオ等から「みなとカードローン」に一本化されており、追加調査は不要だった。
   → 複数商品らしき名前が出てきたら、まず「新規受付中か」を確認する（価格.com等に
   「新規のお申し込み受付が終了した商品です」と明記されることがあり、判断材料になる）。

9. **新しいエリアに着手する前に「地方銀行の公式一覧」で網羅性を確認する（見落とし防止）。**
   東海エリアで、当初「知っている銀行を思い出す」やり方で候補を挙げたところ、
   同格の百五銀行（三重県）を見落とした。全国地方銀行協会や、大阪銀行協会の会員一覧
   （銀行協会の公式サイトに掲載）などで地域の地方銀行リストを確認し、進めている行数と
   照合すると見落としを防げる。実際に確認した結果：
   - 関西（2府4県）＝8行で完成（南都・京都・池田泉州・関西みらい・滋賀・紀陽・みなと・但馬）
   - 東海（静岡・岐阜・愛知・三重）＝**10行**で完成（静岡・スルガ・清水・静岡中央・
     大垣共立・十六・あいち・名古屋・三十三・百五）
   → 次のエリア（東北・関東等）に進む際も、着手前にまず地方銀行の一覧を検索して
   候補をリストアップしてから調べ始めると、この教訓が活きる。

10. **候補一覧を作った後も、近年の合併・統合がないか個別に確認する。**
    東北エリアの候補一覧作成時、当初「青森銀行」「みちのく銀行」を別の2行として数えたが、
    実際は2025年1月1日にすでに合併し「青森みちのく銀行」という1つの銀行になっていた
    （商品も「青森みちのくカードローン」に統合済み）。同様に東海の「愛知銀行」「中京銀行」も
    2025年1月1日に合併し「あいち銀行」（愛知銀行が存続会社）になっており、東海は当初の
    11行ではなく**10行が正しい**（あいち銀行が「愛」「リブレ」「ユー」「C-style」の4商品を持つ形）。
    地方銀行協会等の一覧だけでは合併のタイミングによって情報が古いことがあるため、
    候補一覧を作った直後に「（銀行名） 合併」で個別に検索し、統合済みでないか確認するとよい。
    フィデアHD傘下の荘内銀行・北都銀行のように、**発表済みだがまだ合併していない**
    （2027年1月予定）ケースもあるため、「発表」と「実施済み」を区別して確認する。

## 4. サイト構成（★確定：3階層構造）

エリアごとに独立したページを作る方針（SEO上、エリア名で検索されやすくするため）。

1. **トップページ**（`/`）：サイト全体の入口。9エリアをカードで並べ、公開中/準備中を一目で
   分かるようにする（見本：site-top-page.html）。
2. **エリア別 比較一覧ページ**（例：`/cardloan/kansai/`）… 稼ぎ頭。そのエリアの銀行を
   都道府県ごとに束ねて並べる（見本：kansai-cardloan-compare-sample-v3.html、
   tokai-cardloan-compare-v1.html）。
3. **商品ごとの個別ページ**（例：`/cardloan/tokai/hyakugo-dream/`）：比較表より詳しい内容
   （限度額ごとの金利全段階表、申込条件を1項目ずつ、パンくずリスト、同エリア内の関連商品への
   内部リンク）を載せる（見本：detail-page-hyakugo-dream.html）。
4. 解説記事（補助）：「カードローンの選び方」「金利って何？」など

**内部リンクの方針**：エリアページ同士（例：関西ページの下に「東海のカードローンはこちら」）、
比較ページ→個別ページ、個別ページ→同じ都道府県の他行、の3方向でリンクを張り、回遊を作る。

## 5. ★デザイン方針（確定：v3スタイル）

参考サイト（NP掛け払い）の雰囲気に寄せることに決定。特徴は次のとおり。

- メインカラー：**明るい水色（スカイブルー、目安 #3E9BE0）**
- 背景：ごく薄い水色から白へのグラデーション
- 見出し：**青・太字・左寄せ**＋英語の小見出し（Compare / How to choose 等）＋横線
- 要点に**黄色いマーカー**
- ボタン：青い四角＋「›」矢印（特別なCTAは青→ピンクのグラデーションでも可）
- 下部に**青一色の帯**（注意喚起・免責の誘導に使用）
- **フッターはグレー**、白文字
- カードは白＋うすい水色の枠
- スマホでも見やすいこと（1商品＝1カードで縦に並ぶ）

実装時は、確定した見本HTML（kansai-cardloan-compare-sample-v3.html）をClaude Codeに渡し、
「この見た目のまま、Next.jsのカードローン比較ページにして。各商品を1件ずつ管理できるデータ構造にしたい」と依頼する。
